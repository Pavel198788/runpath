# Промт для Claude Code: PWA «От дивана до марафона»

> Как использовать: открой терминал в пустой папке проекта, запусти `claude`, вставь текст ниже целиком.
> Рекомендую сначала запустить в режиме плана (`/plan` или Shift+Tab → Plan), чтобы Claude сначала показал план и задал вопросы, а потом уже писал код.

## Кто ты и что мы делаем

Ты — старший full-stack инженер и продакт-лид с опытом в спортивных приложениях, а также консультируешься по спортивной физиологии и нутрициологии. Мы вместе с нуля строим публичное веб-приложение (PWA) на русском языке, которое ведёт абсолютного новичка — человека, который никогда не бегал и, возможно, в плохой форме — от первой прогулки до финиша марафона (42,195 км).

Архитектура — **local-first**: приложение полностью работает офлайн, все данные и вся логика (план, питание, нагрузка) живут на устройстве. **Первая цель — полностью автономное приложение, которое можно выложить и пользоваться без какого-либо сервера.** Только после этого добавляется **лёгкий PHP-бэкенд на обычном shared-хостинге** — для того, что нельзя сделать без сервера: аккаунты и синхронизация между устройствами, push-уведомления, OAuth-интеграции (Strava, Garmin), прокси к ИИ с моим ключом (с лимитами) и админка контента. Если сервер недоступен, приложение не должно ломаться — только тихо откладывать синхронизацию.

Рабочее название: **«RunPath»** (можешь предложить 3–5 альтернатив на старте).

## Принципы продукта

1. **Безопасность важнее скорости.** Никаких резких прыжков нагрузки. Всё, что мы советуем, должно быть консервативным и опираться на общепринятые практики беговой подготовки новичков (прогрессия по типу Couch-to-5K → 10 км → полумарафон → марафон, правило ~10% прироста недельного объёма, разгрузочные недели, тейпер перед стартом, бег в разговорном темпе как основа).
2. **Для человека, который ничего не знает о беге.** Каждый термин объясняется простым языком прямо в интерфейсе. Никакого сленга без подсказки.
3. **Адаптивность.** План не высечен в камне: он пересчитывается по фактическим тренировкам, самочувствию, пропускам, болезням и травмам.
4. **Local-first и приватность.** Устройство — источник истины, сервер — резервная копия и мост между устройствами. Пользователь может пользоваться приложением вообще без аккаунта (гостевой режим) и завести его позже, не потеряв данные. На сервере хранится минимум, всё шифруется в транспорте (HTTPS), пароли — только хэши (Argon2id), есть удаление аккаунта одной кнопкой.
5. **Честность.** Приложение не врач и не тренер. Медицинский дисклеймер при онбординге и в настройках, обязательная рекомендация пройти обследование перед началом, «красные флаги» (боль в груди, головокружение, острая боль в суставе) — стоп и совет обратиться к врачу.

## Технический стек (используй именно его, если нет веских причин — тогда обоснуй)

- **Vite + React 18 + TypeScript** (strict).
- **PWA**: `vite-plugin-pwa` (Workbox), полноценный офлайн, `manifest.json`, установка на домашний экран, иконки, splash.
- **Состояние и хранение**: Zustand для UI-состояния, **Dexie.js (IndexedDB)** для всех пользовательских данных с версионируемыми миграциями схемы.
- **Стили**: Tailwind CSS + shadcn/ui-подобные компоненты (без тяжёлых UI-фреймворков). Тёмная и светлая тема, mobile-first, крупные тап-зоны (приложение будут открывать на бегу потными пальцами).
- **Графики**: Recharts (лёгкие).
- **Карты**: Leaflet + OpenStreetMap-тайлы (с кэшированием просмотренных тайлов для офлайна), без API-ключей.
- **Даты**: date-fns с русской локалью.
- **i18n**: сразу заложи инфраструктуру (`react-i18next` или лёгкий аналог), но контент только на русском. Все строки — в файлах переводов, не хардкодом.
- **Тесты**: Vitest + React Testing Library; критичная логика (генератор плана, расчёт нагрузки, калькулятор питания) покрыта юнит-тестами.
- **Качество**: ESLint, Prettier, husky pre-commit, GitHub Actions (lint + test + build). Деплой — статика PWA и `api/` на мой хостинг одной командой (SFTP), см. раздел «Бэкенд».
- Размер бандла держать в разумных пределах; разбивать по маршрутам (lazy).

### Бэкенд (этап B — только после готового автономного приложения; под ограничения shared-хостинга)

- **PHP 8.2+**, Composer, лёгкий фреймворк **Slim 4** (или чистый PHP с роутером — обоснуй), **MySQL/MariaDB** (что даёт хостинг), миграции через Phinx. Никаких долгоживущих процессов, WebSocket'ов и очередей-демонов — всё, что «фоновое», делается через **cron хостинга** (раз в 1–5 минут) и таблицу заданий.
- REST API в `api/` с JSON, версионирование `/api/v1`. Аутентификация: e-mail + пароль (Argon2id), подтверждение почты, сброс пароля; сессии на **JWT access + refresh-токен** в httpOnly-cookie либо в хранилище PWA — выбери и обоснуй. Rate limiting по IP и по пользователю (таблица в БД, без Redis).
- Первым делом напиши `server/CHECK.php` — скрипт, который проверяет, что хостинг умеет: версия PHP, расширения (pdo_mysql, openssl, gmp/bcmath для Web Push, curl, mbstring), cron, HTTPS, лимиты `max_execution_time`/`memory_limit`, `.htaccess`-переписывание. От результата зависит, что реально можно сделать.
- Деплой: сборка PWA в статику + загрузка `api/` по FTP/SFTP или через GitHub Actions (deploy по SFTP). Секреты — в `.env` вне веб-корня, пример в `.env.example`.
- Безопасность: CORS только для нашего домена, CSRF для cookie-сессий, валидация всех входов (schema), prepared statements, заголовки безопасности, логирование ошибок в файл, без утечек стека наружу.

## Функциональные модули

### 1. Онбординг и профиль

- Возраст, пол, рост, вес, текущий уровень активности («не бегал никогда» / «могу пройти 30 минут» / «бегаю 5 км» и т. д.), цель (финишировать марафон / полумарафон как промежуточная цель / просто начать бегать), желаемая дата старта (необязательно) или «без даты — сколько нужно, столько и займёт».
- Ограничения здоровья (чекбоксы: суставы, спина, сердечно-сосудистые, лишний вес, беременность и т. д.) → влияют на консервативность плана и показывают дисклеймер.
- Доступные дни недели и предпочтительное время тренировок.
- Простой тест уровня в первую неделю (например, сколько минут человек может идти/бежать без остановки, или тест 1,6 км) → калибровка стартовой точки.

### 2. Генератор тренировочного плана (ядро приложения)

Чистая, детерминированная, тестируемая функция `generatePlan(profile, history, settings) → Plan`.

- Фазы: **База ходьба/бег интервалами** (≈ 8–12 недель до устойчивых 30 минут бега) → **5 км** → **10 км** → **Полумарафон** → **Марафон** (общая длительность для нулевого новичка обычно 30–52 недели; для «уже бегаю 5 км» — короче).
- Типы тренировок: прогулка, интервалы ходьба/бег, лёгкий бег, длительная (long run), темповая (появляется позже), фартлек, восстановительная, ОФП/силовая, растяжка/мобильность, отдых. Для новичков — 3 беговых дня в неделю, максимум 4–5 ближе к концу.
- Правила: прирост недельного объёма ≤ 10%, каждая 3–4-я неделя — разгрузочная (−20–30%), длительная не более ~30–35% недельного объёма, максимальная длительная перед марафоном 30–32 км, тейпер 2–3 недели.
- Тренировки описываются структурно (сегменты: тип, длительность/дистанция, целевая интенсивность по шкале ощущений RPE 1–10 и «разговорный тест»), чтобы их можно было озвучивать и отображать таймером.
- **Адаптация**: пропуск → сдвиг без «навёрстывания»; пропуск ≥ 2 недель или болезнь → откат на 1–2 недели назад; стабильно слишком тяжёлые ощущения → снижение объёма; хорошее самочувствие несколько недель подряд → допускается плановая прогрессия, не быстрее.
- Возможность ручной правки: перенести тренировку на другой день, отметить как выполненную частично.

### 3. Выполнение тренировки

- Экран «Сегодня»: что делать, зачем (одно предложение), сколько займёт.
- **Встроенный таймер интервалов** с голосовыми подсказками (Web Speech API, русский голос) и вибрацией: «Беги 1 минуту», «Иди 2 минуты», «Осталось 5 минут». Работает при выключенном экране насколько это возможно в PWA (Wake Lock API, фоновая аудиодорожка-«тишина» как известный воркараунд — реализуй и задокументируй ограничения iOS/Android).
- **GPS-трекинг** через Geolocation API: маршрут, дистанция, темп текущий и средний, сплиты по километрам, набор высоты. Фильтрация шума координат (Kalman или простое сглаживание + отбрасывание выбросов по точности). Пауза/автопауза.
- Ручной ввод тренировки (если бегал без телефона): дистанция, время, ощущения.
- После тренировки: RPE, самочувствие, боли (где именно, на схеме тела), заметка, погода (можно вручную).

> Модули 1–3, 7–10, 13 и BYOK-часть модуля 11 — это **этап A (автономное приложение)**. Модули 4, 5, 12, серверная часть 6 и прокси-часть 11 — **этап B (сервер)**.

### 4. Аккаунты и синхронизация _(этап B)_

- Гостевой режим по умолчанию; регистрация по e-mail — опциональна и «поднимает» локальные данные в аккаунт.
- **Синхронизация local-first**: каждая сущность имеет `id` (UUID), `updatedAt`, `deletedAt` (мягкое удаление). Клиент держит очередь изменений (outbox) в IndexedDB и отправляет её, когда есть сеть; сервер отдаёт изменения «после версии N». Разрешение конфликтов — last-write-wins по `updatedAt` для простых сущностей; для журнала тренировок конфликтов быть не должно (append-only). GPS-треки синхронизируются как отдельные сжатые блобы (gzip, polyline-кодирование), чтобы не раздувать трафик.
- Индикатор состояния синхронизации в UI, ручная кнопка «синхронизировать», понятные ошибки.
- Экспорт всех данных в JSON и отдельных тренировок в GPX; резервное копирование/восстановление файлом остаётся для тех, кто не хочет аккаунт.

### 5. Push-уведомления _(этап B)_

- **Web Push (VAPID)** через сервисный воркер: сервер хранит подписки, библиотека `minishlink/web-push`. Отправка — из cron-задания хостинга по расписанию пользователя («напомнить за час до тренировки», «вечером, если сегодня не тренировался», «еженедельный отчёт готов»).
- Важно: на iOS Web Push работает только для установленной на домашний экран PWA (iOS 16.4+) — сделай подсказку по установке и честную проверку поддержки.
- Все уведомления отключаемы по типам; никаких «манипулятивных» пушей.

### 6. Импорт и интеграции _(импорт файлов — этап A; OAuth — этап B)_

- Импорт файлов **GPX / TCX / FIT** (парсеры в браузере) — покрывает Garmin, Polar, Coros, Suunto, Apple Watch через экспорт.
- Импорт CSV-экспорта Strava и «архива» Apple Health (export.xml — потоковый парсинг, файл может быть большим).
- **Strava OAuth** через сервер: одно приложение Strava на весь сервис (мои client id/secret в `.env`), callback на сервере, токены пользователей в БД (шифрованно), обновление refresh-токенов. Webhook Strava (при поддержке хостинга) или опрос из cron → новые пробежки автоматически появляются в приложении. Учитывай лимиты Strava API.
- **Garmin Connect API** — заложи тот же интерфейс провайдера, реализация после одобрения доступа разработчика (это отдельная заявка Garmin; отметь в документации).
- Пользователь всегда видит, откуда пришла тренировка, и может отвязать интеграцию.

### 7. Питание

- Расчёт BMR/TDEE (Mifflin-St Jeor) с поправкой на тренировочную нагрузку **из плана** — калорийность меняется по дням: лёгкий день / день длительной / отдых.
- Макросы для бегуна на выносливость (углеводы 5–7 г/кг в базовой фазе, до 8–10 г/кг на неделе марафона; белок 1,4–1,8 г/кг; жиры остаток), с простым объяснением «почему».
- Цель по весу (снижение / поддержание / без цели) — только мягкий дефицит, не больше ~500 ккал/день, и никакого дефицита на неделях с пиковым объёмом и на тейпере. Предупреждения о рисках недоедания (RED-S) простыми словами.
- **Питание вокруг тренировки**: что съесть за 1–3 часа до, что во время (правило ~30–60 г углеводов/час на длительных > 75–90 минут), что после (окно восстановления). Гидратация и электролиты, подсказки по жаре.
- **Углеводная загрузка** перед марафоном (план на 2–3 дня) и **план питания на день гонки** по часам, с тренировкой желудка на длительных.
- Библиотека продуктов (локальная, ~300–500 базовых позиций с КБЖУ, русские названия) и быстрый дневник: не обязательный, «легковесный» режим — можно просто отмечать «поел нормально / мало / переел».
- Шаблоны рационов и 30–50 простых рецептов с тегами (перед бегом / после / для длительной / вегетарианское).
- Контент про питание пишется отдельными markdown/JSON-файлами в `content/`, чтобы легко редактировать без правки кода.

### 8. Профилактика травм и восстановление

- Мониторинг нагрузки: недельный объём, монотонность, **ACWR** (отношение острой к хронической нагрузке, 7 дней / 28 дней) с зонами «безопасно / осторожно / риск» и понятным объяснением.
- Библиотека упражнений: разминка перед бегом (динамическая), заминка, растяжка, ОФП для бегунов (ягодицы, кор, икры, стопа), мобильность — с текстом и простыми SVG/схемами или анимациями, без видео (офлайн).
- Симптом-чекер по болям (без диагнозов!): «боль в колене сбоку на 3-м км» → вероятные типичные причины у новичков, что сделать (снизить объём, отдых, обувь), когда к врачу.
- Сон, стресс, пульс покоя (вручную) → индекс готовности на сегодня; при плохом — предложение заменить тренировку на лёгкую.
- Напоминания об обуви (пробег кроссовок, замена через ~600–800 км), трекинг пар обуви.

### 9. Геймификация и мотивация

- Визуальный «путь к марафону»: карта прогресса 0 → 42,2 км с этапами; накопительная дистанция «ты уже пробежал столько-то — это как от … до …» (Москва → Тула и т. п.).
- Стрики (с «заморозкой», чтобы не разрушать мотивацию из-за одного пропуска — не поощряем тренировки через болезнь), достижения (первые 30 минут без остановки, первые 5 км, первая длительная 15 км, 100 км суммарно…).
- Еженедельный отчёт «что получилось / что дальше» и уровни («Ходок → Джоггер → Бегун → Полумарафонец → Марафонец»).
- Уведомления (Web Push без сервера невозможен — используй локальные напоминания через Notification API + планирование при открытом приложении, честно опиши ограничения) и виджет-подобный ярлык «Сегодня».
- Виртуальные челленджи (пробежать «дистанцию до Питера» за месяц), опциональный шаринг карточки результата картинкой (Canvas → PNG).

### 10. Обучение и справочник

- Мини-курс «Бег для новичков» в формате коротких уроков, привязанных к неделям плана (техника, дыхание, обувь, одежда по погоде, как выбрать первый старт, что делать на гонке).
- Глоссарий терминов, к которым ведут подсказки из интерфейса.
- Калькуляторы: темп ↔ время на дистанцию, прогноз результата (Riegel), зоны по пульсу (если пользователь знает максимальный пульс), калькулятор целевого темпа на марафоне.

### 11. ИИ-тренер _(BYOK — этап A; прокси — этап B)_

- Базово приложение работает целиком на правилах — ИИ дополняет, а не заменяет.
- **Основной режим — прокси на моём сервере**: `api/v1/ai/*` на PHP пересылает запросы в Anthropic API с моим ключом из `.env`. Ключ никогда не попадает в браузер. Обязательно: доступ только авторизованным, **квоты** (например, N сообщений в день на пользователя и месячный бюджет на весь сервис, настраиваются в админке), лимит длины контекста, счётчик расхода токенов по пользователям в БД, логирование без хранения лишних персональных данных. Стриминг ответа — через SSE, если хостинг позволяет (проверяется `CHECK.php`), иначе обычный ответ.
- **Запасной режим — BYOK**: пользователь может ввести свой ключ (Anthropic или OpenAI-совместимый), тогда запросы идут напрямую из браузера, минуя квоты (для Anthropic — заголовок `anthropic-dangerous-direct-browser-access`, риски объяснены в UI). Ключ хранится только локально.
- Абстракция провайдера единая (`src/ai/providers/`), чтобы UI не знал, откуда приходит ответ.
- Что даёт ИИ: чат с тренером в контексте (профиль, план, последние 4 недели тренировок, самочувствие, питание передаются структурированно); объяснение «почему сегодня такая тренировка»; разбор недели; помощь с рационом; ответы на вопросы новичка. Системный промт тренера — в отдельном файле `src/ai/coachSystemPrompt.ts`: консервативный, безопасный, без медицинских диагнозов, по-русски, опирается только на переданные данные, не выдумывает. Кэшируй системный промт и контекст (prompt caching), чтобы экономить.
