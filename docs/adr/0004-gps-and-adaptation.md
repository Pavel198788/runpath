# ADR-0004. GPS в PWA и механика адаптации плана

Дата: 2026-09-10 · Статус: принято

## GPS

- Источник — Geolocation API `watchPosition` с `enableHighAccuracy`. Точки с точностью хуже 40 м и скачки быстрее 8 м/с отбрасываются; остальное сглаживается одномерным фильтром Калмана по дисперсии точности (`src/domain/geo/filter.ts`).
- Автопауза: нет смещения ≥ 4 м за 6 секунд. После ручной паузы фильтр сбрасывается, чтобы не «дорисовать» линию до нового места.
- Трек хранится в отдельной таблице `tracks` (точки + полилиния + сплиты), запись дневника ссылается на него по `trackId`. Так дневник остаётся лёгким, а трек можно синхронизировать отдельным блобом (этап B).
- Ограничение, которое не обходится в PWA: при заблокированном экране iOS останавливает геолокацию, Android может её ограничивать. Держим экран включённым через Wake Lock и честно пишем это в настройках. Нативный фоновый GPS — только Capacitor (IDEAS).
- Карта — Leaflet в отдельном ленивом чанке (150 КБ) и только на экране записи, не во время бега.

## Адаптация плана

- План хранится как список недель + тренировки с датами. Адаптация делается одной операцией `restructurePlan`: с текущего понедельника вставляются копии нужных недель (при болезни — уменьшенные вдвое, только лёгкий бег), остаток плана сдвигается вперёд. Выполненные и частично выполненные тренировки не трогаются; запланированные на прошедшие дни текущей недели не пересоздаются.
- Решение принимается по итогам полностью прошедших недель (`decideAdjustment`) и предлагается пользователю, а не применяется молча. Применённые корректировки хранятся в `planAdjustments`, чтобы не повторять одну неделю бесконечно.
- Любая перестройка проходит проверку `validatePlanSafety` в тестах.
